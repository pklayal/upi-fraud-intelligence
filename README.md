# UPI Fraud & Risk Intelligence

A two-layer fraud analytics system combining:
- **Macro layer** (Dataset A — 250,000 UPI transactions, full year 2024): business KPIs, geography, bank, and merchant-category fraud patterns.
- **Micro/behavioral layer** (Dataset B — 6,126 device-level risk-tagged transactions): ML-based fraud risk scoring using device fingerprinting, retry velocity, and behavioral signals.

Built as an MBA Capstone Project (Data Science).

## Project structure

```
upi-fraud-intelligence/
├── data/
│   ├── raw/                          # original Kaggle CSVs (not modified)
│   └── cleaned/                      # star schema output of clean_pipeline.py
├── scripts/
│   ├── clean_pipeline.py             # raw -> cleaned star schema
│   ├── compute_metrics.py            # cleaned -> KPIs (dashboard/metrics.json)
│   └── train_model.py                # trains Isolation Forest + XGBoost, compares vs rule-based score
├── models/                           # saved .pkl models (generated)
├── dashboard/
│   ├── app.py                        # Streamlit dashboard (5 pages)
│   └── metrics.json                  # generated by compute_metrics.py
├── reports/                          # generated markdown/json reports
├── requirements.txt
└── README.md
```

## 1. Local setup

```bash
git clone <your-repo-url> && cd upi-fraud-intelligence
python3 -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements.txt
```

Place the two raw CSVs in `data/raw/`:
- `upi_transactions_2024.csv`
- `fraud_risk_signals.csv`

## 2. Run the pipeline (in order)

```bash
python3 scripts/clean_pipeline.py     # -> data/cleaned/*.csv, reports/data_quality_report.md
python3 scripts/compute_metrics.py    # -> dashboard/metrics.json, reports/business_metrics_summary.md
python3 scripts/train_model.py        # -> models/*.pkl, reports/model_comparison.md
```

## 3. Run the dashboard locally

```bash
streamlit run dashboard/app.py
```

Open the URL Streamlit prints (usually `http://localhost:8501`).

The dashboard has 5 pages (sidebar navigation):
1. **Overview** — daily volume, transaction type split, merchant categories, hourly patterns
2. **Fraud & Disputes** — fraud rate by state and bank
3. **Geographic & Bank Risk** — transaction distribution by state/bank/device/network
4. **Behavioral Risk (ML)** — device-level risk explorer, agent-type behavioral segments
5. **Model Comparison** — rule-based score vs Isolation Forest vs XGBoost, with feature importance

## 4. Deploying online (free — Streamlit Community Cloud)

This is the easiest way to get a shareable link for your viva/report.

### Step-by-step

1. **Push your project to GitHub**
   ```bash
   cd upi-fraud-intelligence
   git init
   git add .
   git commit -m "Initial commit: UPI fraud risk intelligence project"
   git branch -M main
   git remote add origin https://github.com/<your-username>/upi-fraud-intelligence.git
   git push -u origin main
   ```
   Important: `data/raw/upi_transactions_2024.csv` is ~30MB. GitHub allows files up to 100MB, so it's fine to commit directly — but if you want a smaller repo, add it to `.gitignore` and instead commit only `data/cleaned/` (the dashboard only reads from `data/cleaned/`, so raw files aren't needed to run the deployed app).

2. **Make sure the generated files are committed**
   The dashboard reads from `data/cleaned/`, `dashboard/metrics.json`, `models/`, and `reports/model_comparison.json`. Run all three scripts locally first (step 2 above) so these generated files exist, then commit them too — Streamlit Cloud won't run your pipeline scripts automatically, it only runs `app.py`.

   ```bash
   git add data/cleaned dashboard/metrics.json models reports
   git commit -m "Add generated pipeline outputs"
   git push
   ```

3. **Sign up / log in at Streamlit Community Cloud**
   Go to https://share.streamlit.io and sign in with your GitHub account.

4. **Deploy the app**
   - Click **"New app"**
   - Select your repository: `<your-username>/upi-fraud-intelligence`
   - Branch: `main`
   - Main file path: `dashboard/app.py`
   - Click **"Deploy"**

5. **Wait for the build**
   Streamlit Cloud installs everything from `requirements.txt` automatically. This takes 2-5 minutes. Watch the logs on screen for errors.

6. **Get your public link**
   You'll get a URL like:
   `https://<your-username>-upi-fraud-intelligence.streamlit.app`

   This is the link you put in your project report and share with your viva examiner.

### Common deployment issues and fixes

| Problem | Fix |
|---|---|
| `FileNotFoundError: dashboard/metrics.json` | You forgot to run and commit the generated files (step 2 above) |
| `ModuleNotFoundError: xgboost` | Confirm `requirements.txt` is in the repo root, not inside a subfolder |
| App builds but shows blank charts | Check that `data/cleaned/*.csv` were committed, not just `data/raw/` |
| Repo too large / slow push | Add `data/raw/*.csv` to `.gitignore`; the deployed app doesn't need raw files, only `data/cleaned/` |
| App sleeps after inactivity | Free tier apps sleep after ~7 days of no traffic — just reopen the link and click "Wake up app" |

## Notes on data leakage (important for your Results chapter)

The raw `fraud_risk_signals.csv` dataset includes a `fraud_score` column that the dataset's own generator used *to derive* the `is_suspicious` label. If you include `fraud_score` (or `agent_type`, which is similarly correlated) as a model input, XGBoost trivially reaches ~100% accuracy by copying that column — which is not a genuine result. `train_model.py` deliberately excludes both from the feature set so the model has to learn risk from raw behavioral signals (velocity, attempt count, amount, timing) instead. This is a good, honest discussion point for your viva if asked about model validity.
